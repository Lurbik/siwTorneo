⚡ Analisi Prestazioni

Confronto tra strategie di caricamento JPA su N tornei, N squadre totali, N partite totali.

🐢 LAZY (default)

Carica le relazioni solo quando vengono accedute. Genera il problema N+1: una query per i tornei, poi una query per ogni torneo per squadre e partite.


—

Query generate: N

⚡ JOIN FETCH squadre

Carica tornei e squadre in una sola query con JOIN SQL. Elimina N+1 per le squadre.


—

Query generate: 1

🚀 JOIN FETCH partite

Carica tornei e partite in una sola query con JOIN SQL. Elimina N+1 per le partite.


—

Query generate: 1

📊 Conclusioni

La strategia LAZY è comoda ma pericolosa in produzione: con molti record genera decine o centinaia di query inutili.

JOIN FETCH risolve il problema N+1 caricando tutto in una query con JOIN SQL. È la soluzione raccomandata quando sai in anticipo che avrai bisogno delle relazioni.

Il trade-off: JOIN FETCH carica sempre tutto, anche se non serve. Per casi complessi si usa @EntityGraph per specificare esattamente cosa caricare caso per caso.
